# Glosario

| Término | Qué significa |
|---|---|
| **Motor (engine)** | Programa base para hacer juegos (física, gráficos, sonido). Usamos Godot. |
| **Escena (.tscn)** | En Godot, cualquier "pieza": un personaje, un nivel, un menú. Se anidan unas dentro de otras. |
| **Nodo** | Componente dentro de una escena (una malla 3D, una cámara, un sonido…). |
| **Script (.gd)** | Archivo de código GDScript que da comportamiento a un nodo. |
| **Asset** | Cualquier recurso: modelo 3D, textura, sonido, animación. |
| **Low-poly** | Modelos 3D con pocos polígonos; estilo limpio y barato de dibujar para la GPU. |
| **FPS** | Imágenes por segundo. 60 = fluido. |
| **VRAM** | Memoria de la tarjeta gráfica. La tuya: 3 GB. |
| **Hitbox / Hurtbox** | Zona invisible que *hace* daño (espada) / zona que *recibe* daño (cuerpo). |
| **i-frames** | Fotogramas de invulnerabilidad durante una esquiva. |
| **Postura** | Barra de Sekiro: si se llena, el personaje queda expuesto. |
| **Desvío (parry/deflect)** | Bloquear justo a tiempo: anula el daño y castiga la postura del enemigo. |
| **Telegrafiar** | Que el enemigo "avise" visualmente antes de atacar. |
| **Lock-on** | Fijar la cámara en un enemigo. |
| **FSM (máquina de estados)** | Forma de organizar comportamiento: el personaje está en UN estado (atacando, esquivando…) y pasa a otro según reglas. |
| **IA** | En juegos, el comportamiento de los enemigos (no tiene que ver con IA generativa). |
| **Vertical slice** | Una porción pequeña del juego hecha con calidad final, para probar que la idea funciona. |
| **Prototipo** | Versión fea (cubos) para probar si algo es divertido. |
| **Git / commit** | Sistema de historial; cada commit es un punto al que se puede volver. |
| **CC0** | Licencia "dominio público": puedes usar el asset para lo que quieras, incluso vender. |
| **Exportar** | Generar el `.exe` del juego para jugarlo sin Godot. |
